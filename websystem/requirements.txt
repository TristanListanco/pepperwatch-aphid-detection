# Pepper Watch runtime dependencies.
#
# Python floor is 3.11 and the ceiling is <3.14. Both current Raspberry Pi OS
# releases are supported: Bookworm ships 3.11, Trixie (Oct 2025) ships 3.13.
# Ranges rather than exact pins, so one manifest resolves cp311 and cp313
# wheels alike. Development happens on 3.11 deliberately — building against
# the floor is what stops 3.12+ syntax reaching a Bookworm field unit.
#
# On the Pi, create the venv with --system-site-packages: Picamera2 and its
# libcamera bindings are apt-only (sudo apt install python3-picamera2) and pip
# cannot build working bindings. That flag has a sharp edge — see the numpy
# note below and run `python -m pepperwatch.doctor` after installing.

Flask>=3.1,<4
gunicorn>=23.0,<24         # gthread worker, one process, so the SSE Hub is shared
paho-mqtt>=2.1,<3
onnxruntime>=1.22,<2       # cp311 and cp313 aarch64 wheels both present
opencv-python-headless>=4.11,<5   # headless keeps GTK/Qt off the Pi; <5 avoids the new major
psutil>=7.0,<8
Pillow>=11.1,<12           # thumbnails for the historical gallery

# numpy is deliberately loose. On a --system-site-packages venv, pip-installing
# a pinned numpy SHADOWS apt's numpy, and libcamera's C bindings were compiled
# against apt's. That ABI mismatch is a real and common Picamera2 failure, so
# prefer whatever apt already provides on the Pi and let pip fill in only where
# apt has none (CI). `python -m pepperwatch.doctor` probes for exactly this.
numpy>=1.24,<3

# Installed by deploy/install.sh rather than pinned here:

#   python3-picamera2               apt, not pip (libcamera bindings)
#   HailoRT (hailo_platform)        apt: hailo-all or hailo-h10-all, when an
#                                   AI HAT+ is on the PCIe bus
